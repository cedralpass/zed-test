# Python Development Environment Setup Plan

This document outlines the recommended Python development setup for the **Wind Kite Picker App**. The goal is to use modern, high-performance tools that ensure reproducibility, ease of use, and seamless integration with CI/CD and editors like Zed.

## 🎯 Recommendation: The `uv` Workflow

After researching current best practices and comparing traditional methods (`pyenv`, `venv`, `pip`) with modern alternatives, I strongly recommend using **`uv`** as the primary tool for all Python-related tasks.

### Why `uv`?

| Feature | `pyenv` + `venv` + `pip` | `uv` (Recommended) |
| :--- | :--- | :--- |
| **Complexity** | Requires managing 3+ separate tools. | **Single, unified tool** for everything. |
| **Speed** | Standard `pip` installation speeds. | **10-100x faster** than `pip`. |
| **Python Mgmt** | Manual installation via `pyenv`. | **Automated** version management. |
| **Reproducibility** | `requirements.txt` (often drift). | **`uv.lock`** (deterministic & robust). |
| **Cross-Platform** | Primarily Unix-centric. | **True cross-platform** support. |

## 🛠 Proposed Setup Details

### 1. Python Version & Management
- **Standardized Version**: Python **3.13** (the latest stable version, fully supported by Flask).
- **Tool**: `uv` will manage the Python installation and version pinning.
    - A `.python-version` file will be committed to the repository to ensure everyone uses the same version.

### 2. Dependency & Environment Management
- **Dependency Declaration**: Use `pyproject.toml` (the modern Python standard) instead of `requirements.txt`.
- **Locking**: `uv` will generate a `uv.lock` file. This file **must be committed** to ensure every developer and the CI/CD pipeline use the exact same dependency tree.
- **Virtual Environment**: A `.venv` directory will be created and managed by `uv` within the project root.

### 3. Project Structure
The project will evolve toward a structure compatible with Flask best practices:
```text
.
├── .python-version       # Pinned Python version (generated by uv)
├── .gitignore            # Configured to ignore .venv, __pycache__, etc.
├── pyproject.toml        # Project metadata and dependencies
├── uv.lock               # Deterministic lockfile (DO COMMIT)
├── README.md
├── app.py                # Main Flask application entry point
├── constants.py          # Application constants
├── engine.py             # Core calculation logic
├── test_engine.py        # Unit tests
├── templates/            # HTML templates (Jinja2)
└── static/               # Static assets (CSS, JS, Images)
```

### 4. Editor & CI/CD Integration
- **Zed Editor**: Zed will be configured to automatically discover the Python interpreter located at `./.venv/bin/python`.
- **CI/CD (e.g., GitHub Actions)**: The CI pipeline will use `astral-sh/setup-uv` to quickly install `uv`, set up the environment, and run tests.
- **Production**: The deployment process will use `uv pip install --system -r pyproject.toml` or similar to create a lightweight, production-ready environment.

## 🚀 Execution Plan

If this plan is approved, I will run the following commands to initialize the environment:

```bash
# 1. Install uv (if not already present)
brew install uv

# 2. Initialize the project with uv (creates pyproject.toml)
uv init

# 3. Install the desired Python version
uv python install 3.13

# 4. Pin the project to Python 3.13
uv python pin 3.13

# 5. Add Flask as a dependency (creates uv.lock)
uv add flask

# 6. Verify the setup by running existing tests
uv run python -m unittest test_engine.py
```

## 📝 Git Strategy
- **Commit**: `pyproject.toml`, `uv.lock`, `.python-version`.
- **Ignore**: `.venv/`, `__pycache__/`, `.pytest_cache/`, `.DS_Store`.
